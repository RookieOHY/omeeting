## Backlog（暂不做，已确认记录）

### 💤 收听房定位（决策记录）

环境音房间（当前唯一的房间类型）为**纯收听房**：全员只能听、不能开麦。UI 已以「🎧 纯收听」徽章表达。
→ 未来 WebRTC 语音通话将作为**另一种房间类型**（开麦房）实现，SFU 的 publish 能力只服务于开麦房。

### 💤 来日需求 A：媒体源接入（广播电台 / 视频平台音频 / 直播流 / 音乐）

支持在房间内播放：广播 FM 流、主流视频平台的视频对应音频、直播流、音乐 playlist（含功能 #2「一起听歌」是其子集）。

**落点提示（开工时考虑）：**
- 播放器统一抽象： `<audio>`/HLS (hls.js) / ICEcast(mp3/aac)/YouTube 等多源
- **同步策略二选一**：a) 服务器转码转发（稳、但算力/版权重） b) 各端本地拉流 + 控制信令同步（seek/play/pause 广播给全房，最省后端）
- **风险**：YouTube/B站等平台音频"搬运"违反其 ToS 也涉版权；只做「用户自选流 URL / 公开电台 / 自有音乐库」，平台音频只做本地播放不落不转发
- 依赖：#3 文字聊天的 WS 通道（同步信令复用）

### 💤 来日需求 B：房间任务（一个人开房填任务 + 执行时间）

单人开房即可发布任务；任务含内容与执行时间；到时提醒。

**落点提示（开工时考虑）：**
- 单人版可先 localStorage + Notification API 桌面提醒，零后端
- 多人可见/协同版依赖 #3 WS：任务 CRUD 广播 + 到点服务端推送提醒
- UI 建议挂在房间页右侧栏或独立 tab（声景 dock 之上）
